# n8n Gate 0 workflow-as-code lane

This repository-only lane produces nine inactive n8n 2.19.5 candidates from exactly six protected source exports. It never imports to, activates, or binds credentials in a shared/live n8n instance.

## Protected inputs

The closed registry pins all six IDs/names and the canonical SHA-256 of every full source object; the release manifest also records each exact raw-file SHA-256. Raw exports remain outside Git in a `0700` directory as `0600` regular files. Release generation is local-only and fails if any one of the six files is absent, renamed, symlinked, non-regular, malformed, duplicate-keyed, invalid UTF-8, over bounds, or byte/semantic drifted. CI synthetic fixtures are explicitly unit-only and are never production evidence.

```sh
node scripts/n8n-workflows.mjs serialize \
  /protected/login.json /protected/bootstrap.json /protected/profile.json \
  /protected/sessions.json /protected/revoke.json /protected/logout.json \
  --out /tmp/pkc-n8n-nine
```

The output directory must not exist. It receives six corrected workflows, the founder MFA finalizer, projection-only outbox dispatcher/reconciler, customer-only rollback login, and a manifest. All files are mode `0600`; workflows are inactive, identity-free, unpublished, retry-disabled, and `none/none/false/false` for execution retention. Generated candidates and raw snapshots are never committed.

## Semantic readback and privacy

```sh
node scripts/n8n-workflows.mjs compare expected.json exported-readback.json
node scripts/n8n-workflows.mjs privacy /tmp/pkc-n8n-nine/*.json
```

The comparator tolerates only native IDs and native timestamps/version metadata. It fails on nodes, connections, code, settings, webhook paths, credential names/types, active state, and retention. Retention hardening is prospective and does **not** claim historical execution/log purge.

## Founder `account_id` backfill

The planner consumes a sanitized inventory only, proves exactly one `PK Blick` admin row, rejects duplicates and partial signals, ignores email as authority, and emits a dry-run plan. It never writes.

```sh
node scripts/n8n-founder-account-backfill-cli.mjs plan inventory.json <approved-uuid> backfill-plan.json
```

Apply exists only as the injected `applyBackfillPlan` seam. The operator must supply the typed receipt derived independently from the immutable plan digest; plans do not contain an approval answer. The adapter must return raw mutation, readback, cardinality, and failed-second-mutation rows. Code derives exact-one, uniqueness, and immutability and rejects adapter booleans. This CLI deliberately exposes no apply command.

## Disposable native rehearsal

`ops/n8n-disposable/rehearse.mjs` uses only the locally installed immutable `n8nio/n8n@sha256:b1b0c592735e24acd3cc64db83f94ef4efd8e331e47c6883249cc51cc1bea16b` image (`pull_policy: never`), and requires the same RepoDigest in the release manifest. It uses cancellation-safe asynchronous process groups, bounded output/timeouts, nonce-scoped Compose resources and temp roots, and treats cleanup failure as failure without hiding the primary error. It imports exactly nine inactive artifacts and performs semantic native readback plus zero active/credential/execution/published-webhook checks.

Run only against generated sanitized artifacts:

```sh
node ops/n8n-disposable/rehearse.mjs /tmp/pkc-n8n-nine
```

`npm run test:contracts` is the clean-checkout CI lane. It excludes the protected-source and permission-isolated gate files. `npm run test:contracts:protected:synthetic` runs the mandatory shared gate engine on independently pinned synthetic authority under the Node 24 permission model: repository reads are allowlisted, writes are confined to a dedicated temporary directory, and child-process creation is denied. Its sync, callback, promise, stream, and child-process probes prove the OS/runtime boundary against a harmless test-only denied canary. This is gate-engine and mutation coverage, not production snapshot evidence. `npm run test:contracts:protected` is the explicit local release-gate lane for the exact mode-`0600` protected inputs and executes the same shared topology, founder tuple, response allowlist/validator, query cardinality, privacy, and serialization assertions. Only that protected-source lane proves exact six-source transformation and emitted-byte hashes. Disposable rehearsal proves import/readback compatibility only for those exact generated bytes. None of these gates authorizes production import, activation, credential binding, webhook registration, runtime execution, data migration, or historical purge; each remains a separate operator-approved gate.

The dispatcher database authority is literal-pinned in `scripts/n8n-outbox-db-contract.mjs`. It permits only the six accepted outbox claim/complete/unknown/reconciliation procedures, exact argument/result envelopes, exact PostgreSQL casts, and exact `queryReplacement` cardinality. `PKC_MFA_OUTBOX_WORKER_ID` is mandatory explicit n8n environment configuration and must already be a canonical lowercase UUID before either claim query runs. The composition helper can compare the combined tree's `db/migrations/001_founder_mfa.sql` to the pin by setting `PKC_MFA_DB_MIGRATION_PATH` during the contract test.

The founder finalizer stays on the protected login workflow's reviewed account/session/audit projection authority. It does not reference the previously proposed `pkc_auth.read_founder_account` or `pkc_auth.finalize_founder_mfa_session` functions because no matching `CREATE FUNCTION` signatures exist in this repository's migration authority. Finalizer generation inventories every `pkc_auth.*(...)` call in PostgreSQL nodes and rejects any signature absent from `db/migrations/*.sql`; missing database authority blocks generation rather than manufacturing compatibility functions. The response passes through an exact-key/type validator and an explicit response expression, so unknown fields fail closed instead of being returned wholesale.

Delivery adapters receive the closed database claim envelope (`outbox_id`, `operation_key`, `operation_type`, payload, canonical decimal-string `lease_fence`, attempts, and configured UUID `worker_id`). Only a confirmed matching operation key with a validated 64-character lowercase receipt digest can complete; every other delivery result uses `mark_founder_mfa_outbox_unknown` with a database-allowed class. Reconciliation has a separate claim fence: confirmed matching readback calls `reconcile_founder_mfa_outbox`, while absent or unconfirmed readback calls `defer_founder_mfa_outbox_reconciliation`. There is no blind redispatch or worker-owned terminal transition.

Permanent CI validates code, synthetic fixture units, and discriminating mutations only. It cannot claim protected-source release evidence unless all exact protected inputs are explicitly provisioned. Import, activation, credentials, static/import validation, runtime behavior, and production mutation remain separate gates.
