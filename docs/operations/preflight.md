# Production preflight

## Authority

This is an operator checklist, not authorization. It binds to approved plan SHA-256 `7f9b6d6f5c17e80649e42fefd860f476160be6bd1a809511543e4a27814e5454`. Obtain a separate approval for each database, key, n8n retention, inactive import, Preview activation, merge, Production configuration, cutover, enrollment, and destructive-cleanup stage. A generic continuation never crosses stages.

## Procedure

1. Freeze local review bytes with a disposable `GIT_INDEX_FILE`: initialize it from `HEAD`, add the complete working candidate with `git add -A`, write the candidate tree with `git write-tree`, and remove the disposable index. Never point these commands at the real index. Recompute the temporary tree twice and require equality. This local tree is review evidence only; it is not deployment authority. After acceptance and commit, all deployment evidence must bind the clean committed Git commit and tree read back from GitHub and the provider.
2. Require the approved exact candidate tree for local review and the clean committed candidate SHA/tree for deployment. Repository diagnostic scanning rejects non-finite/negative-zero canonical data; unbounded or changed files; any root/ancestor/leaf symlink or descriptor whose exact containment and device/inode/mode/size/mtime/ctime identity cannot be proven before and after read; UTF-8 BOM, NUL, malformed/overlong/surrogate or non-roundtripping text; database dumps/databases; ad-hoc screenshots/images; logs; Playwright output; unapproved reports; sensitive paths/extensions; credential-prefix markers; and every sensitive RHS except exact reviewed placeholders or simple literal-free JavaScript runtime references. The only admitted SQL authorities are `db/migrations/*.sql` and the exact case-sensitive paths `db/roles/000_roles.sql`, `db/roles/005_unseal_migrator.sql`, and `db/roles/010_seal_migrator.sql`; all admitted SQL authorities must be canonical UTF-8 text and remain credential-marker and sensitive-assignment scanned. Treat every `.sh`, `.bash`, `.dash`, `.ksh`, or `.zsh` file and every text beginning with `#!` as executable text regardless of interpreter spelling. In that lane `#` is not a suppression boundary: unsafe sensitive assignments in comments, URL fragments, quoted or escaped contexts, continuations, substitutions, or GNU `env` forms must fail. The executable lane additionally admits only an exact `$NAME`, `${NAME}`, `"$NAME"`, or `"${NAME}"` sensitive RHS, with `NAME` matching `[A-Za-z_][A-Za-z0-9_]*`; single quotes, direct command/arithmetic substitution, static literals, prefixes/suffixes, fallback or indirect expansion, concatenation, and compound expressions remain rejected. This is a bounded lexical allowance, not shell parsing or environment interpretation, and it makes no claim that indirection is safe. Exact approved placeholders may pass. The scanner does not claim to detect `eval`, indirect expansion, or dynamically constructed variable names. Unknown extensionless text without `#!` keeps generic conservative comment handling. Reviewed app source assets are admitted only by the explicit narrow source-asset policy. Confirm no provider credentials, raw workflow exports, dumps, logs, screenshots, browser storage, or secret artifacts are tracked.
3. Read back only variable names/scopes, workflow IDs/version/settings, database metadata, immutable snapshot IDs, deployment IDs, alias targets, and rollback pointers. Never read values.
4. Confirm customer traffic and founder mode for the named stage, restore proof, monitoring policy, operator identities, maintenance window, and stop conditions.
5. Fill a mutation receipt before action with closed digest-only prior-state authority `{stateReceiptId,stateDigest}` and an immutable rollback handle. After action, fill the same closed new-state reference and independent verification evidence. A successful receipt is invalid unless every verification item is `pass`; failed checks require a separate failure record, not a successful mutation receipt.

## Stop conditions

Stop on digest/SHA/tree drift, missing approval, missing immutable backup ID, Preview/Production confusion, nonzero disposable residue, secret-bearing output, retention drift, an unknown transaction outcome, or provider inventory mismatch. Gate 0 performs no live preflight and claims no rehearsal.
